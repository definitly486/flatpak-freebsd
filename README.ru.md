# flatpak-freebsd

Запуск Flatpak-приложений на **FreeBSD** через **Linuxulator**, без установки Flatpak и OSTree.

`flatpak-freebsd` — это лёгкая реализация на Python для загрузки, установки и запуска приложений из Flatpak/OSTree-репозиториев на FreeBSD.

Программа напрямую обращается к OSTree-репозиторию по HTTP, восстанавливает приложение и его runtime, а затем запускает Linux ELF-бинарники с использованием Linuxulator FreeBSD.

> **Это не полноценная реализация Flatpak и она не предоставляет изоляцию безопасности Flatpak.**

## Возможности

* Запуск Linux Flatpak-приложений на FreeBSD
* Использование Linuxulator FreeBSD
* Не требует установки пакета `flatpak`
* Не требует установки `ostree`
* Прямой доступ к OSTree-репозиториям по HTTP
* Поддержка Flathub
* Поддержка Flathub Beta
* Автоматическая загрузка runtime приложений
* Параллельная загрузка объектов
* Инкрементальные обновления
* Атомарное обновление приложений
* Автоматическое определение ELF-интерпретатора
* Автоматическое формирование путей к библиотекам runtime
* Автоматическое создание wrapper-скриптов
* Опциональные отдельные XDG-каталоги для приложений
* Простой интерфейс командной строки
* Написано на Python 3

## Как это работает

В отличие от обычного Flatpak, этот проект не использует Flatpak daemon, командные инструменты OSTree, Bubblewrap или Linux namespaces.

Основной процесс выглядит следующим образом:

```text
Flatpak-репозиторий
       │
       │ HTTP
       ▼
flatpak-freebsd.py
       │
       ├── чтение OSTree refs
       ├── чтение commit
       ├── чтение дерева каталогов
       ├── загрузка объектов
       ├── восстановление файловой системы
       │
       ▼
Приложение + Runtime
       │
       ▼
Linux ELF-бинарник
       │
       ▼
ld-linux из Runtime
       │
       ▼
FreeBSD Linuxulator
```

Приложение локально восстанавливается из OSTree-объектов. При запуске Linux-бинарник выполняется через динамический загрузчик, предоставляемый соответствующим Flatpak runtime.

## Требования

* FreeBSD с поддержкой Linuxulator
* Python 3
* Доступ в Интернет
* Совместимое Flatpak-приложение и runtime

Перед запуском приложений Linuxulator должен быть настроен и работоспособен.

Проверить его наличие можно командой:

```sh
kldstat | grep linux
```

В зависимости от конфигурации FreeBSD может потребоваться загрузить модуль Linuxulator:

```sh
doas kldload linux
```

## Установка

Клонируйте репозиторий:

```sh
git clone https://github.com/definitly486/flatpak-freebsd.git
cd flatpak-freebsd
```

Сделайте скрипт исполняемым:

```sh
chmod +x flatpak-freebsd.py
```

При необходимости установите его в `PATH`:

```sh
doas install -m 755 flatpak-freebsd.py /usr/local/bin/flatpak-freebsd
```

После этого:

```sh
flatpak-freebsd --help
```

## Каталог данных

По умолчанию приложения и runtime сохраняются в:

```text
~/.local/share/flatpak-freebsd
```

Расположение можно изменить с помощью:

```sh
flatpak-freebsd --root /path/to/root ...
```

или переменной окружения:

```sh
export FLATPAK_FB_ROOT=/path/to/root
```

Каталог данных содержит приложения, runtime, метаданные и автоматически созданные wrapper-скрипты.

## Использование

### Установка приложения

```sh
flatpak-freebsd install APP_ID
```

Например:

```sh
flatpak-freebsd install org.example.Application
```

Необходимый runtime приложения устанавливается автоматически.

### Запуск приложения

```sh
flatpak-freebsd start APP_ID
```

### Запуск через `run`

```sh
flatpak-freebsd run APP_ID
```

Также приложение можно запускать через созданный для него wrapper-скрипт.

### Список установленных приложений

```sh
flatpak-freebsd list
```

### Информация о приложении

```sh
flatpak-freebsd info APP_ID
```

### Обновление

Обновить конкретное приложение:

```sh
flatpak-freebsd update APP_ID
```

Либо выполнить обновление установленных приложений в соответствии с доступными параметрами команды:

```sh
flatpak-freebsd update
```

### Удаление приложения

```sh
flatpak-freebsd remove APP_ID
```

### Создание ссылки

```sh
flatpak-freebsd link APP_ID
```

### Создание wrapper

```sh
flatpak-freebsd wrap APP_ID
```

### Проверка установки

```sh
flatpak-freebsd check APP_ID
```

## Структура установленных приложений

Установленное приложение содержит восстановленную Flatpak-файловую систему и метаданные с информацией о runtime и запуске.

Концептуально структура выглядит следующим образом:

```text
~/.local/share/flatpak-freebsd/
├── apps/
│   └── APP_ID/
│       ├── ...
│       ├── info.json
│       └── env
├── runtimes/
│   └── RUNTIME_ID/
│       └── ...
├── env
└── ...
```

Точная структура управляется приложением и обычно не должна изменяться вручную.

## Runtime и запуск ELF

Flatpak-приложения обычно ожидают собственное Linux runtime-окружение.

Поэтому `flatpak-freebsd` не запускает приложение напрямую:

```sh
./application
```

Вместо этого программа определяет ELF-интерпретатор, предоставляемый runtime, например:

```text
lib/ld-linux-x86-64.so.2
```

и запускает приложение через этот загрузчик.

Концептуально это соответствует:

```sh
/path/to/runtime/lib/ld-linux-x86-64.so.2 \
    --library-path /path/to/runtime/lib:... \
    /path/to/application
```

Таким образом приложение использует библиотеки из Flatpak runtime, а Linux-системные вызовы предоставляются Linuxulator FreeBSD.

## `/app`

Flatpak-приложения обычно ожидают наличие своих файлов в:

```text
/app
```

Если это возможно, `flatpak-freebsd` создаёт:

```text
/compat/linux/app
```

как ссылку на установленное приложение.

Если необходимые каталоги нельзя изменить автоматически, программа выводит команду, которую необходимо выполнить с соответствующими привилегиями.

## Окружение

Launcher предоставляет набор стандартных значений переменных окружения, предназначенных для запуска графических Linux-приложений на FreeBSD.

Например:

```text
GDK_BACKEND=x11
QT_QPA_PLATFORM=xcb
GSK_RENDERER=cairo
LIBGL_ALWAYS_SOFTWARE=1
GTK_A11Y=none
NO_AT_BRIDGE=1
```

Также используются настройки WebKit для приложений, которые не могут использовать свой обычный Linux sandbox:

```text
WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1
WEBKIT_DISABLE_COMPOSITING_MODE=1
```

Это именно совместимые обходные настройки, и они могут быть неподходящими для некоторых приложений.

## X11

В текущей реализации графические приложения ориентированы на X11.

Например:

```sh
echo $DISPLAY
```

обычно должно вывести что-либо вроде:

```text
:0
```

Если `DISPLAY` не установлен, launcher предупреждает, что графическое приложение может не получить доступ к X-серверу.

## Изоляция приложений

Опция `--isolate` позволяет использовать отдельные XDG-каталоги для приложения:

```text
~/.var/app/APP_ID/
├── config/
├── data/
├── cache/
└── state/
```

Это **только организация файлов и окружения**.

Это не является sandbox безопасности.

## Безопасность

### Важно

`flatpak-freebsd` **не предоставляет изоляцию безопасности**, которую обычно обеспечивает Flatpak.

В проекте отсутствуют аналоги полноценного Flatpak sandbox, основанные на:

* Bubblewrap
* Linux namespaces
* seccomp-фильтрации
* ограничении доступа к устройствам
* ограничении сети
* отдельном mount namespace
* системе разрешений Flatpak

Поэтому установленное приложение потенциально может получить доступ к ресурсам, доступным Linuxulator, в соответствии с правами пользователя, от имени которого оно запущено.

В частности, в качестве обходного решения для совместимости намеренно используется:

```text
WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1
```

Запускайте только те приложения, которым вы доверяете.

## Обновления

Приложения синхронизируются с использованием OSTree commit references.

Обновление выполняется через промежуточный каталог и атомарную замену каталога приложения, а не изменением уже установленного дерева непосредственно.

Концептуально:

```text
текущее приложение
        │
        ├── загрузка обновления
        ▼
    APP.new
        │
        ├── успешно
        ▼
    атомарный rename
        │
        ▼
обновлённое приложение
```

Это снижает вероятность того, что после прерванной загрузки останется частично обновлённое приложение.

## Загрузка

OSTree-объекты загружаются непосредственно из репозитория.

Процесс загрузки:

1. Читается reference приложения.
2. Получается commit.
3. Разбираются метаданные commit.
4. Обходится дерево OSTree.
5. Собираются необходимые файловые объекты.
6. Объекты загружаются параллельно.
7. Распаковываются `.filez`-объекты.
8. Восстанавливаются файлы, каталоги и символические ссылки.
9. Повторно используются идентичные объекты, когда это возможно.

Для ускорения загрузки используется несколько worker-потоков.

## Архитектура

Текущая реализация поддерживает:

```text
x86_64
aarch64
```

Соответствующая архитектура Linux и путь к динамическому загрузчику выбираются автоматически.

Основной целью разработки и тестирования в настоящее время является x86_64 FreeBSD.

## Ограничения

Проект намеренно значительно меньше полноценной реализации Flatpak.

Текущие ограничения:

* Нет Flatpak sandbox
* Нет Bubblewrap
* Не требуется командная утилита OSTree
* Нет Flatpak daemon
* Нет полной системы разрешений Flatpak
* Графическая среда ориентирована на X11
* По умолчанию включён программный рендеринг
* Некоторые приложения могут потребовать дополнительной настройки
* Приложения, зависящие от недоступных через Linuxulator возможностей ядра, могут не работать
* Приложения, требующие штатный Flatpak sandbox, могут не работать
* Аппаратное ускорение может потребовать отдельной настройки для конкретного приложения

Таким образом, успешная установка приложения ещё не гарантирует его успешный запуск.
